# Contributing to SokoFlow

Thanks for your interest! SokoFlow is built for African businesses and every
good contribution makes it stronger.

## Ground rules

- **Zero AI by design.** This project deliberately contains no ML, LLMs, or
  predictive features. Please don't "helpfully" add any.
- **Boring is a feature.** Favor deterministic, auditable, testable code.
- **Small PRs.** One logical change per pull request.
- **Regional code works.** Our users live in Rwanda, Kenya, Uganda and beyond —
  offline-first and low-bandwidth friendly always.

## Getting started

The MVP scaffold is defined in [docs/ROADMAP.md](docs/ROADMAP.md). Before you
contribute, read it so your work lands in the right place.

1. Fork the repository
2. Create a branch: `git checkout -b feat/your-feature`
3. Make your changes
4. Run tests and linting if present
5. Commit with a clear message
6. Open a pull request against `main`

## Pull request checklist

- [ ] Describe *what* changed and *why* in the PR description
- [ ] Reference any related issue
- [ ] No unrelated changes or renames
- [ ] README/docs updated if behaviour changed

## Code style

Follow the conventions of the codebase you are touching. When unsure, match
the surrounding code. No comments unless they explain *why* (not *what*).

## Code of conduct

All contributors must follow our [Code of Conduct](CODE_OF_CONDUCT.md).

## Questions

Open a Discussion — we actively read them and appreciate every single one.
